# 이 프로젝트 기술 총정리 — 개념 설명, 한계점, 더 공부해야 할 것

최종 갱신: 2026-07-30 (후보 풀 확장 작업 반영)

이 문서는 발표/질의응답에서 "이게 무슨 기술이고 왜 썼냐"는 질문에 스스로 답할 수 있도록, 지금까지 나온 모든 기술 요소를 하나씩 풀어서 설명한다. 각 항목은 **① 무엇인가 ② 왜/어디에 썼는가 ③ 이 프로젝트에서 어떻게 동작하는가 ④ 한계·열린 질문** 순서로 구성했다.

> **읽는 순서**: 결과 수치는 `이력기반_후보풀확장_작업보고서.md`가 정본이다. 이 문서는 그 결과를 이해하는 데 필요한 **개념 설명**과 **한계 정리**를 담는다. 두 문서가 어긋나면 보고서를 따를 것.

**데이터 규모** (전 구간 공통): train 6,141 방문 / eval 1,286 / test 1,255. 학습 표본은 (방문 × 확장된 후보) 쌍으로 152,258개.

## 0. 큰 그림 — 전체 파이프라인

```
[1] 원본 HI-DR (사전학습·검증 완료, 이번 작업에서 미수정)
    환자 히스토리 → (Cross-Visit Attention + Gumbel-Softmax + GCN) → encode()
                  → Beam Search decode() → 방문별 약물 후보 + 로그확률
                  → candidates_{train,eval,test}.pt 로 1회 캐싱

[2] 후보 풀 확장 (이번 작업의 핵심)
    빔 후보 ∪ 그 환자의 직전 방문 처방  →  정답 커버리지 0.6325 → 0.7665

[3] 재점수화 (DrugFilterHead, 작은 MLP)
    방문 임베딩 + 약물 임베딩 + HI-DR 로그확률 + 이력 피처 6종 + is_beam
    → "이 약이 실제 처방에 있었을 확률"

[4] Threshold 선택 + 평가
    eval에서 "품질 하한 + 안전마진" 제약 하에 threshold 선택 → test 적용
```

`[1]`은 원래 있던 것이고 `[2]~[4]`가 이번 작업이다. **`[2]`가 이 프로젝트의 실질적 기여**다 — `[3]`, `[4]`는 그 풀을 정확히 깎아내기 위한 장치다.

## 1. 원본 HI-DR(HEIDR)이 쓰는 기술

이 절의 기술들은 전부 **건드리지 않았다.** 다만 무엇인지는 설명할 수 있어야 한다.

### 1.1 Beam Search (빔서치)

**무엇인가**: 약물 시퀀스를 한 개씩 생성할 때, 매 스텝 1등만 남기는 게 아니라 상위 K개(`BEAM_SIZE=4`)를 동시에 유지하며 탐색하는 방법. 그리디보다 전체 시퀀스 확률이 높은 조합을 찾을 가능성이 크다.

**여기서 어떻게 쓰이나**: `HEIDR/beam.py`의 `Beam` 클래스가 방문 하나당 1개 생성되고, 매 스텝 `model.decode()`가 내놓는 다음 약물의 확률분포를 받아 후보를 갱신한다(`advance()`). 최대 45스텝까지 반복.

**한계 — 그리고 이번 작업이 발견한 것**: 빔서치가 내놓는 후보 풀이 **정답 약물의 63.25%만 담는다.** 더 심각한 건, **"직전 처방을 그대로 반복"하는 자명한 베이스라인이 같은 크기에서 65.43%를 덮는다** — 빔서치 출력 전체보다 많다. 이번 작업은 이 문제를 **우회**(두 풀을 합침)했을 뿐 **해결하지 않았다.** 빔서치 자체의 개선(예: `BEAM_SIZE` 증가, 디코딩 전략 변경)은 범위 밖이다.

### 1.2 Transformer 기반 Decoder (`MedTransformerDecoder`)

**무엇인가**: 트랜스포머 디코더. 이전에 생성한 약물들과 인코더가 만든 질병/방문 정보를 어텐션으로 참조하며 다음 약물을 예측한다.

**한계**: 내부 구조(어텐션 헤드 수, 레이어)는 들여다보지 않았다 — "검증된 블랙박스"로 다뤘다.

### 1.3 Cross-Visit Attention (방문 간 어텐션)

**무엇인가**: 과거 방문 여러 개 중 "지금과 관련 있는 방문"에 더 큰 가중치를 주는 어텐션. `calc_cross_visit_scores()`에서 `F.softmax(diag_scores / att_tau)`로 계산한다. `att_tau`(기본 20)가 클수록 여러 방문에 가중치를 고르게 분산한다.

**한계**: `att_tau=20`이 최적인 근거는 원 논문의 탐색 결과를 그대로 받아 썼다.

### 1.4 Gumbel-Softmax (미분 가능한 이산 선택)

**무엇인가**: "이 과거 방문을 참고할지 말지"처럼 **이산적인 0/1 선택**은 미분이 안 돼서 역전파로 학습할 수 없다. Gumbel-softmax는 softmax에 Gumbel 노이즈를 섞고 `hard=True`로 실제 0/1을 내보내면서, 역전파 시에는 부드러운 근사의 그래디언트를 흘려보내는 재파라미터화 트릭이다(straight-through estimator).

**여기서**: `F.gumbel_softmax(gumbel_input, tau=self.gumbel_tau, hard=True)`, `gumbel_tau=0.6`.

**한계**: 확률적 근사이므로 샘플링 노이즈가 있다. 추론 시 결정성이 보장되는지는 이번 작업에서 검증하지 않았다.

### 1.5 GCN / Directed GCN (그래프 신경망)

**무엇인가**: 그래프 구조를 입력받아 각 노드 임베딩을 이웃 정보로 갱신하는 신경망. 여기서는 **방향성** 그래프(`DirectedGCNConv`)를 써서 "A 다음에 B가 자주 처방된다" 같은 비대칭 관계를 표현한다. `torch_geometric`의 `MessagePassing` 기반.

**여기서**: `weighted_confidence_directed_ehr_graph.pkl`(약물 간 동시처방 패턴)로 약물 임베딩(`drug_memory`)을 만든다.

**한계**: 그래프 자체의 생성 방식은 원본 전처리 산출물을 그대로 받아 썼다.

### 1.6 VITA 사전학습 임베딩 + top-k 유사 방문

**무엇인가**: 별도 사전학습 모델(VITA)이 각 방문마다 "가장 유사한 다른 방문 top-3"을 미리 계산해둔 것.

**여기서**: 각 방문의 입력 시퀀스를 "자기 히스토리 + 유사 방문 top-3 필러 + 현재 방문"으로 구성한다.

**한계 — 지표 비교 시 반드시 주의할 점**: **필러로 섞인 유사 방문까지 포함해 평가하면(원 논문 방식) Jaccard가 0.66대, 현재 방문만 떼서 보면 0.45대가 나온다.** 이 구분을 놓치면 숫자 비교가 완전히 틀어진다. 실제로 이 프로젝트에서 한 번 혼선이 있었고, "현재 방문만"이 필터 비교의 올바른 기준으로 확정됐다. **원 논문 벤치마크(Jaccard 0.6653, AVG_MED 30.19)와 이번 결과를 직접 비교하면 안 된다.**

### 1.7 DDI 인접행렬 (`ddi_A_final.pkl`)

**무엇인가**: 약물 M×M 0/1 행렬. `ddi_A[i,j]==1`이면 i와 j를 함께 처방할 때 상호작용 위험이 알려진 조합. 외부 의학 DB에서 구축된 지식.

**한계**: "알려진 위험 조합"만 담는다 — 미지의 상호작용, 개인차(신장/간 기능)는 전혀 반영하지 않는다. **"DDI rate가 낮다 = 임상적으로 안전하다"로 치환하면 과장이다.**

## 2. 이번 작업이 쓰는 기술

### 2.1 후보 풀 확장 — 이 프로젝트의 핵심

**무엇인가**: 빔서치가 놓친 정답을 되찾기 위해, 후보 풀을 `빔 후보 ∪ 직전 방문 처방`으로 넓힌다. 빔서치를 다시 돌리지 않고 캐시를 읽는 단계에서 합치므로 비용이 거의 없다.

**왜 효과가 있나**: 빔이 놓친 정답 7.53개/방문 중 34.3%가 직전 방문에 있고, 추가되는 후보 6.08개 중 42.4%가 실제 정답이다. MIMIC에서 반복 입원 시 만성질환 약물이 계속 처방되기 때문이다.

**구현 세부** (`candidate_pool.py`의 `expand_candidates`):
- 빔이 낸 적 없는 약물에는 HI-DR 확률이 없으므로, **그 방문 빔 후보의 최소 로그확률을 sentinel로** 준다.
- **`is_beam` 이진 플래그**를 함께 넣어 모델이 두 출처를 구분할 수 있게 한다.
- 중복 제거, 순서 고정(빔 먼저 → 이력 약물 오름차순)으로 결정론 보장.

**성과**: 커버리지 0.6325 → **0.7665**. 이 값은 학습·난수와 무관한 결정론적 값이라 5개 seed 전부 소수점 4자리까지 동일하다.

**한계**:
- "전체 이전 방문"을 다 합치면 0.7883까지 오르지만 풀이 27.75개로 커지는데 Jaccard는 +0.004밖에 안 올라서, **직전 방문만** 쓰는 단순한 쪽을 택했다.
- 첫 방문(이전 방문 없음)에는 확장할 것이 없다. 다만 데이터셋 구성상 모든 레코드가 최소 1개의 이전 방문을 갖는다.
- 이 성질은 **MIMIC의 반복 입원 구조에 의존**한다. 초진 환자 위주 데이터셋에서는 통하지 않을 것이다.

### 2.2 처방 이력 피처 6종

**무엇인가**: 후보별 스칼라 6개 — `in_prev`(직전 방문에 있었나), `in_any_prev`, `frac_prev`(등장한 과거 방문 비율), `n_prev`(과거 방문 수), `prev_size`(직전 처방 크기 ÷ 131), `recency_weighted`(최근 방문에 0.5^age 가중).

**얼마나 강한 신호인가**:
- P(정답 | 직전 방문에 있음) = **0.7370** vs P(정답 | 없음) = **0.3895** (기준율 0.6295)
- 단일 피처 AUC: `frac_prev` 0.679, `in_prev` 0.659 — **HI-DR 자신의 로그확률(0.676)과 동급**
- 후보 중 정답인 것의 **80.9%가 직전 방문에 존재**

**누수가 없는 이유 (구조적)**: `compute_history_features(prev_med_sets, candidate_ids)`는 현재 방문 정답을 **인자로 받지 않는다.** 이력은 `patient[:idx]`(과거만)로 만든다. 시그니처를 고정하는 테스트가 있다.

**한계**: `n_prev`만 정규화 안 된 raw 값(보통 1~3)이고 나머지 다섯은 [0,1]이다. 선형층에 들어가는 스케일이 불균형하지만 목표치를 달성했으므로 재튜닝하지 않았다 — 결과가 미달했다면 여기가 첫 번째 손볼 곳이었다.

### 2.3 이진분류 MLP (`DrugFilterHead`) + BCEWithLogitsLoss

**무엇인가**: 은닉층 1개짜리 작은 다층 퍼셉트론. 입력 = 방문 임베딩 64 + 약물 임베딩 64 + HI-DR 로그확률 1 + `extra_features` 7(이력 6 + `is_beam` 1) = **136차원** → Linear(128) → ReLU → Linear(1) → 시그모이드. 손실은 `BCEWithLogitsLoss`(시그모이드+로그손실을 수치안정적으로 합친 것).

**왜 이렇게 작나**: HI-DR이 이미 강한 신호를 주므로 "재채점"만 하면 된다는 설계 철학. 학습이 17초~30초에 끝난다.

**중요 — 이름 정정**: 입력의 `hidr_logprob`는 예전에 `hidr_prob`로 불렸는데 **실제로는 로그확률(항상 음수)**이다. 이 잘못된 이름이 실제 버그를 유발했으므로(§2.6) 이름을 바로잡았다.

**한계**: 모델이 단순해서 "왜 이 약을 걸렀는지" 설명력이 낮다. 임상 적용을 논한다면 별도 과제.

### 2.4 Threshold 선택 — 안전 마진이 핵심

**무엇인가** (`select_min_avgmed_threshold`): eval split에서 "필터 전(확장 풀 전체) Jaccard + 안전마진 0.005" 이상을 유지하는 threshold 중 AVG_MED가 가장 낮은 것을 고르고, test에 적용한다.

**안전 마진이 왜 필요한가 (winner's curse)**: 제약을 **딱 맞게** 만족하는 지점을 고르면, eval에서는 경계 안쪽이지만 test에서는 넘어간다. 실측으로 확인됐다 — 마진 0이면 5-seed 중 test 제약을 만족한 게 **3/5**, threshold 격자를 50→1000개로 촘촘히 하면 **1/5로 더 나빠졌다.** 격자를 정밀하게 할수록 나빠지는 것이 경계 과적합의 교과서적 증상이다. 마진 0.005를 주면 **5/5**가 된다. `N_THRESHOLDS=50`도 같은 이유로 고정된 값이며 **숨은 튜닝 파라미터**다.

**한계**: `min_recall_ratio` 같은 잔여 하이퍼파라미터는 여전히 원칙적 도출이 아니라 합리적 기본값이다.

### 2.5 평가 프로토콜 — 동일 크기 비교

**무엇인가**: 풀을 넓히면 처방 크기가 달라지므로, **단일 운영점 비교가 무의미해진다.** 그래서 (AVG_MED, Jaccard) 곡선을 보고하고 세 지점(13.0 / 16.85 / 20.07)에서 비교한다.

**20.07이 주 지점인 이유 — 흔한 오해**: 20.07은 **정답 처방 크기가 아니다.** 정답은 20.16이고, 20.07은 **구 시스템(빔-only 풀)이 실제 운영되던 크기**다. 이 지점을 고르는 이유는 구 필터의 Jaccard 0.4550이 바로 거기서 측정됐기 때문에 — 같은 크기에서 비교해야 "풀을 키워 크기를 부풀린 덕에 좋아 보인다"는 반론을 막을 수 있다.

**필수 동반 보고**: **제거된 정답 약물 수/방문**. 구 필터는 방문당 1.38개의 정답을 지우면서 이 수치를 한 번도 보고하지 않았다. 현재 설계는 **3.07개**다(풀이 커졌으므로 절대 삭제량도 늘었다).

### 2.6 제거된 것 — DDI 충돌 피처 (반증 기록)

**원래 무엇이었나**: 같은 방문 내 다른 후보와의 DDI 충돌 강도를 피처 2개(`conflict_sum_norm`, `conflict_max`)로 넣어 모델이 상호작용을 인지하게 하려 했다.

**발견된 버그**: `hidr_prob`가 확률이 아니라 **로그확률(항상 음수)**이었다. `conflict_max`는 0.0에서 시작해 `max(0.0, 음수)`를 하므로 **168,046개 후보 전량에서 정확히 0** — 수학적으로 죽은 입력이었다. 학습된 모델의 해당 가중치가 초기값 그대로임(그래디언트가 흐른 적 없음)까지 확인됐다.

**그런데 고쳐도 아무 차이가 없었다**: 4개 변형(버그 상태 / exp로 수정 / 단순 충돌 개수로 교체 / 완전 제거)이 **모든 지표에서 서로의 5-seed 노이즈 안**에 들어왔다. 기여도 |w|·std가 0.0058로 로그확률(0.0848)의 1/15 수준. 그래서 **제거**했다.

**교훈**: 이름이 거짓말을 하면(확률이 아닌데 `prob`) 실제 버그가 난다. 그리고 **버그를 고치는 것과 성능이 오르는 것은 별개 문제**다.

### 2.7 반증된 방향들 (다시 파지 않기 위한 기록)

| 시도 | 결과 | 근거 |
|---|---|---|
| 후보 간 self-attention | **MLP보다 나쁨** (AUC 0.7863 < 0.7903) | 용량 키우면 train AUC 0.850→0.905, test 0.789→0.778 — 순수 과적합. 병목은 구조가 아니라 데이터 양(6,141 방문) |
| 방문별 적응 컷오프 / 정답 개수 예측 | **완벽한 오라클조차 Jaccard를 떨어뜨림** (0.4481 < 필터 전 0.4550) | 손실은 컷오프가 아니라 랭킹에서 발생 |
| Greedy 순차 구성 (충돌 시 거부) | DDI rate를 0으로 만들지만 **recall −32%** | 정답 처방 자체에 상호작용 조합이 이미 존재하므로 무조건 거부는 정당한 병용까지 제거 |
| threshold 목적함수 튜닝 | **노이즈의 1/6** 차이 | 같은 점수 벡터에 threshold만 바꾸는 것이라 같은 Pareto 곡선 위 이동일 뿐 |
| 빔 순위 / 전역 약물 사전확률 / 진단 동시출현 피처 | 전부 노이즈 내 | 진단 동시출현이 무효라는 건 `visit_emb`가 이미 진단 정보를 충분히 담았다는 뜻 |

## 3. 검증에 쓰인 통계 기법

### 3.1 Seed Variance + 변동계수(CV)

**무엇인가**: 학습에는 가중치 초기화·셔플 순서 등 무작위성이 있다. seed 0~4로 5번 재학습해 "우연히 좋았던 것"인지 "재현되는 패턴"인지 본다. **CV** = 표준편차÷평균으로, 지표별 스케일 차이를 정규화해 노이즈 크기를 비교 가능하게 한다.

**한계**: 5회는 분산 추정에 넉넉하지 않다. 또 이건 **학습의 우연성**만 검증한다 — **어느 환자가 train에 들어갔는지의 우연성**(완전한 k-fold CV)은 빔서치 재실행 비용 때문에 여전히 미검증이다.

### 3.2 Paired Wilcoxon Signed-Rank Test / Paired t-test

**무엇인가**: 같은 방문을 두 조건에서 측정한 뒤 **짝지어** 차이를 보는 검정. 환자 개인차 노이즈가 상쇄돼 일반 검정보다 강력하다. t-test는 정규성을 가정하고, Wilcoxon은 순위만 쓰는 비모수 버전 — 둘이 같은 결론이면 정규성 가정과 무관하게 견고하다.

**p-value란**: "차이가 없다"는 전제 하에 이 정도 차이가 우연히 나올 확률.

**한계 — 반드시 알아야 할 함정**: **p-value는 "우연이 아니다"만 말하고 "효과가 크다"는 말하지 않는다.** n=1255면 아주 작은 차이도 유의하게 나온다. 실제로 이 프로젝트에서 F1-only vs DDI-aware의 precision 차이가 **유의하지만 크기는 ±0.0015**로 무의미한 수준이었다.

### 3.3 부트스트랩 (Bootstrap Resampling)

**무엇인가**: 갖고 있는 표본에서 **복원추출**로 같은 크기 표본을 2000번 다시 뽑아 매번 통계량을 계산해 분포를 직접 관찰하는 방법. 이론적 분포 가정 없이 신뢰구간을 얻는다.

**왜 DDI rate에 이걸 쓰나**: DDI rate는 방문별 값이 아니라 "전체를 합친 하나의 비율"이라 방문별 짝검정을 바로 못 쓴다. 그래서 방문 단위로 리샘플링한다.

### 3.4 Monte Carlo eval/test 재분할

**무엇인가**: eval+test 방문 풀(2,541개)을 10번 무작위로 다시 나눠, 결론이 "하필 이 분할이라서" 나온 게 아닌지 본다.

**이번 결과 — 중요**:
- "DDI-aware가 필터 안 건 것보다 낫다" → 5개 지표 전부 **10/10 일관**
- "DDI-aware가 F1-only보다 낫다" → 6개 지표 전부 **0/10** (반복마다 우열이 뒤집힘)

### 3.5 평가지표 정의 — Macro 평균의 함정

- **Precision** = 예측 중 맞은 비율, **Recall** = 정답 중 맞춘 비율, **F1** = 둘의 조화평균, **Jaccard** = 교집합/합집합
- **매크로(macro)**: 이 프로젝트는 방문마다 지표를 계산한 뒤 **방문 간 평균**을 낸다(`util.py`의 `average_f1`).

**실제로 있었던 버그**: F1을 "평균 precision과 평균 recall로부터 역산"(mean-of-ratio)하는 실수를 했다. 두 방식은 다른 값을 낸다 — 평균을 어느 단계에서 내느냐에 따라 결과가 달라진다. 이 버그로 한때 "Greedy가 기존 필터를 이긴다"고 잘못 결론 냈다가 공식을 통일해 정정했다.

**교훈**: **지표 이름이 같아도 계산 순서가 다르면 다른 숫자가 나온다.** 다른 논문과 비교할 때는 정의부터 맞춰야 한다.

### 3.6 비율(Rate) vs 절대량 — 분모 효과

**무엇인가**: DDI rate = 위험쌍 / 전체 약물쌍. 필터링은 제거만 하므로 분자·분모가 둘 다 줄지만, **분모가 더 빨리 줄면 비율은 오른다.** "비율이 올랐다"가 직관적으로 "나빠졌다"로 읽히지만 실제로는 둘 다 줄었을 수 있다.

**그래서**: 비율만 보지 않고 **방문당 평균 위험쌍 개수(절대량)**를 함께 본다.

**이번 결과**: 확장 풀 기준 before 27.69쌍/방문 → after 17.58, **5개 seed 전부 감소(−31.0%~−41.4%)**.

**주의 — 베이스라인 불일치 사고**: 이 수치를 처음 측정할 때 "필터 전"을 빔-only 풀로, "필터 후"를 확장 풀로 계산하는 오류가 있었다. 서로 다른 집합을 비교한 것이다. 그 상태에서는 5개 seed 중 3개에서 노출이 **증가**하는 것으로 나왔고, 자칫 "DDI 피처를 제거해서 나빠졌다"고 잘못 진단할 뻔했다. 기준선을 고치자 뒤집혔다. **구 보고서의 −21.6%는 빔-only 기준선 값이라 이 수치와 비교 불가능하다.**

### 3.7 오라클 상한 — 그리고 그 함정

**무엇인가**: "완벽한 분류기"가 도달할 수 있는 상한을 계산해 개선 여지를 재는 방법.

**한계 — 실제로 오해했던 것**: 오라클 AVG_MED 12.64를 "목표"로 착각했는데, 그건 **완벽 분류기의 부산물**일 뿐이다(정답은 20.16개). 완벽한 개수 예측으로 12.64에 도달시키면 Jaccard가 **0.4481로 필터 전보다 나빠진다.** 상한을 목표로 삼기 전에 "그 지점이 실제로 좋은 지점인가"를 먼저 확인해야 한다.

### 3.8 런타임 가드 — 조인 오류 방어

**무엇인가**: 캐시된 후보와 원본 환자 기록을 순회 순서로 맞추는(조인) 구조라, 어긋나면 **모든 결과가 조용히 무효**가 된다.

**실제로 증명된 위험**: test 캐시에 eval 이력을 잘못 짝지어 돌리면 예외 없이 1286→1255로 잘리고 커버리지가 **0.7497**로 나온다 — 0.6325 대비 여전히 큰 개선처럼 보여서 아무도 의심하지 않을 숫자다. 그래서 `build_scoring_inputs`에 길이 검사와 `gt_ids` 표본 대조를 넣어 즉시 예외를 던지게 했다. 세 split 전부에서 `gt_ids`가 순서까지 100% 일치하는 것도 테스트로 고정돼 있다(한 칸만 밀면 일치 0건).

## 4. 전체 한계점 (우선순위순)

1. **빔서치 자체가 개선되지 않았다.** "직전 처방 반복"이 빔서치보다 커버리지가 높다(0.6543 vs 0.6325)는 것은 원 모델에 대한 심각한 소견이며, 이 프로젝트는 우회했을 뿐이다.
2. **DDI-aware 설계의 우위가 입증되지 않았다.** 재분할 0/10, 절대 노출량에서 F1-only와 비슷, ddi_rate 부트스트랩에서 오히려 근소하게 높음(+0.0002, P(diff≥0)=0.999) — **3중 독립 증거로 반박된다.**
3. **배포 지점과 헤드라인 지점이 다르다.** 배포는 Jaccard ≈0.503(AVG_MED 15.9), 헤드라인 0.5231은 크기 맞춘 별도 지점(20.28). 혼동하면 성능을 과대 보고한다.
4. **제거되는 정답 약물이 3.07개/방문**으로 구 필터(1.38)보다 늘었다. 풀이 커진 대가다.
5. **train 표본의 우연성 미검증** — 완전한 k-fold CV는 빔서치 재실행 비용 때문에 미수행.
6. **DDI 인접행렬의 불완전성** — 알려진 조합만, 개인차 미반영.
7. **MIMIC 반복 입원 구조 의존** — 이력 신호의 강도가 이 데이터셋 특성에 기댄다. 다른 코호트 일반화는 미검증.
8. **해석 가능성** — 작은 MLP라 "왜 이 약을 걸렀는지" 설명을 못 준다.
9. **원 논문 벤치마크와 직접 비교 불가** — 평가 슬롯 구성이 다르다(§1.6).

## 5. 발표 전 더 알아두면 좋은 것 (예상 질문 대비)

- **Transformer attention의 Q-K-V 수식** — 이 문서는 "무엇을 위해 쓰였나"만 다뤘다. "cross-visit attention이 정확히 어떻게 계산되나"를 물으면 `calc_cross_visit_scores()`를 더 봐야 한다.
- **Gumbel-softmax의 reparameterization trick 수식** — "왜 이산 선택이 미분 가능해지는가"를 수식으로 답하려면 지금 수준(직관 설명)으로는 부족하다.
- **GCN의 message passing 수식** — `DirectedGCNConv`가 이웃 정보를 어떻게 집계하는지 코드 레벨로 아직 안 뜯어봤다.
- **다중 라벨 지표의 관례 차이** — §3.5의 macro 버그에서 보듯 "같은 이름, 다른 계산"이 흔하다.
- **p-value와 표본 크기의 관계** — "n이 크면 사소한 차이도 유의하다"는 함정을 정확히 설명할 수 있어야 §4-2의 정직한 서술을 방어할 수 있다.
- **winner's curse / 선택 편향** — 안전 마진의 근거(§2.4)를 설명할 때 필요하다.
- **왜 self-attention이 과적합했는가** — 파라미터 수 대비 데이터 양(6,141 방문) 관점에서 설명할 수 있으면 좋다.
