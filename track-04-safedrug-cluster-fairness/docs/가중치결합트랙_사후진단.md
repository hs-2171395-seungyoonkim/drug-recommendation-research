## 1. "CCS 매핑 적용" — 구현되지 않았다

Track 1 을 만든 `scripts/42c_chapter_cluster.py` 는 CCS 를 쓰지 않는다.
ICD-9 **챕터**(3자리 코드 구간을 17개로 자르는 것)를 직접 if-elif 로 적어 넣었다.
프로젝트 어디에도 CCS 파일이 없었다(`grep -ri "ccsr\|dxref"` → 0건).

챕터와 CCS 는 다른 물건이다. 챕터는 "소화기계" 하나에 궤양·간경변·장폐색·췌장염이
전부 들어간다. CCS 는 그것을 283개 임상 범주로 나눈 AHRQ 표준이다.
챕터를 쓰면 이렇게 된다 — 이게 Track 1 이 뭉개져 보인 이유다:

| 챕터 | 방문 |
|---|---|
| 심혈관 | 4,181 |
| 소화기 | 1,962 |
| 외상/중독 | 1,961 |
| … | … |
| 정신과 | 98 |
| 혈액 | 73 |
| 피부 | 59 |
| 선천 | 34 |
| **임신** | **4** |

**그래서 원안대로 CCS 를 실제로 붙였다.** AHRQ HCUP Single-Level CCS for ICD-9-CM
2015판(`$dxref 2015.csv`, 코드 15,072 → 범주 283)을 `ref/ccs_dxref_2015.csv` 로
넣고 `scripts/57_ccs_track.py` 를 만들었다. 결과(`out/table80_ccs_groups.csv`):

- 14,444 방문 중 **14,201건 매핑 성공, 매핑불가 0건.** 나머지 243건은 애초에
  `SEQ_NUM=1` 이 없는 방문이다.
- 코호트에 등장한 CCS 범주 **193개**. 그중 200명 이상은 **20개**, 100명 이상은 31개.
- 미리 정한 규칙(200명 미만은 '기타(소규모)' 로 병합, 버리지 않음)을 적용하면
  주 분석 그룹은 22개.

**여기서 정직하게 적어야 할 것 하나.** CCS 로 바꿔도 꼬리 문제가 사라지지 않는다.
'기타(소규모)' 가 **5,054명(35.0%)** 이다. 193개 범주 중 173개가 200명 미만이라
그렇다. 챕터는 큰 덩어리 5개 + 부스러기였고, CCS 는 중간 덩어리 20개 + 더 긴 부스러기다.
"CCS 로 바꾸면 깔끔해진다" 가 아니라 **"CCS 로 바꾸면 큰 덩어리가 임상적으로 말이 되는
20개로 쪼개지고, 대신 35%가 잔여 범주로 남는다"** 가 맞는 서술이다.

대신 얻은 것은 확실하다. CCS 범주는 챕터 순도가 95~100% 로 챕터 안에 그대로 포개지고
(알코올 관련 59.5% 는 예외인데, 정신과와 소화기에 걸치는 게 임상적으로 맞다),
각 범주 안의 코드들이 같은 병이다 — 아래 4번에서 이게 왜 중요한지 나온다.

## 2. "V_main × 5" — 부진단을 3.8% 로 줄인 것과 같다

`scripts/41w_weight_embed.py` 50~55행이 이렇게 되어 있다:

```python
E_main /= norm(E_main)      # 단위벡터
E_sub  /= norm(E_sub)       # 단위벡터
E_concat = concat([E_main * 5.0, E_sub])
E_concat /= norm(E_concat)
```

두 블록이 각각 단위벡터라 결합 벡터의 코사인 유사도는 정확히 이렇게 분해된다:

> cos = (w² · cos_main + cos_sub) / (w² + 1)

실제 배열로 20,000쌍을 재서 확인했다(최대오차 2.7e-07). **가중치는 제곱으로 들어간다.**
w=5 면 25 : 1 이고, 부진단 기여분은 **1/26 = 3.8%** 다.
의도는 "주진단을 5배 중요하게" 였는데 실제로는 "부진단을 26분의 1로" 였다.

w 를 0부터 ∞까지 쓸어 본 결과(`out/table78_weight_wsweep.csv`, 다른 조건은 전부 동일):

| 구성 | 부진단 기여 | 실루엣 | 주진단만 쓴 것과의 ARI |
|---|---|---|---|
| w=0 (부진단만) | 100% | 0.041 | 0.026 |
| w=1 (반반) | 50% | 0.262 | 0.683 |
| w=2 | 20% | 0.351 | 0.720 |
| w=3 | 10% | 0.375 | 0.652 |
| **w=5 (출하판)** | **3.8%** | **0.382** | **0.702** |
| w=10 | 1% | 0.385 | 0.756 |
| w=∞ (주진단만) | 0% | **0.385** | 1.000 |

읽는 법: **w=5 의 실루엣 0.382 는 부진단을 통째로 버린 0.385 와 사실상 같다.**
0.05 → 0.38 의 도약은 가중치가 만든 게 아니라 **부진단을 버려서** 생겼다.
가중치는 그 버리는 일을 완곡하게 한 것뿐이다.

그리고 버린 것에 정보가 없지 않았다. w=0(부진단만) 분할과 주진단만 쓴 분할의
ARI 가 **0.026** 이다 — 거의 무관한 두 개의 분할이다. 서로 다른 정보를 갖고 있었는데
한쪽을 3.8% 로 눌러 버린 것이다.

## 3. 그림 두 장은 같은 좌표를 쓰고 있었다

이전 `viz_clusters.py` 26~33행이 UMAP 을 **딱 한 번** 계산해서 `umap_df` 하나를 만들고,
Track 1 과 Track 2 가 그것을 각각 merge 했다. **두 그림의 점 위치는 완전히 같고 색만
다르다.** 그래서 이전 리포트의 이 두 문장은 사실이 아니었다:

- 11행 "그림의 2D 좌표(UMAP)는 … **Baseline 임베딩** 공간입니다" → 아니다. 가중치 임베딩이다.
- 22행 "**새로 추출한 가중치 임베딩으로 UMAP을 다시 그렸기 때문**입니다" → 다시 안 그렸다.

지적에 없던 것 하나 더 찾았다. Track 2 의 색(`primary_cluster`)은 **concise** 로
군집한 결과인데, 좌표는 **long** 임베딩에서 뽑은 것이었다(26행 `emb_dxtext_weight_long.npz`).
`long_k30` 과 `concise_k30` 의 ARI 는 0.536 이다. **군집한 공간과 그린 공간이 다르다.**

**고쳤다.** `viz_clusters.py` 를 2×2 로 다시 짰다 — 행 = 좌표계(기본/가중치),
열 = 라벨(CCS/가중치 k-means). `out/figs/fig42_space_vs_label.png`.
같은 라벨을 두 좌표계에 얹어 보면 바로 보인다: **윗줄은 무슨 색을 칠하든 뿌연 덩어리
하나고, 아랫줄은 무슨 색을 칠하든 섬으로 부서진다.** 모양은 좌표계가 정하지 라벨이
정하지 않는다.

## 4. 섬이 생긴 진짜 이유 — 환자가 아니라 ICD 사전을 그렸다

`E_main` 은 주진단 **한 문장**을 인코딩한 것이다. 그 문장의 종류가 몇 개인지 셌다:

| | 개수 |
|---|---|
| 방문 | 14,444 |
| `concise_main` 고유 텍스트 | **1,221** |
| `concise_sub` 고유 텍스트 | 14,374 |

14,444명이 주진단 축에서는 **1,221개 점 위에 겹쳐 앉는다.** 그 축이 유사도의 96.2%다.
UMAP 이 그린 섬 하나하나는 환자 집단이 아니라 사전 표제어다.
(숫자로 세면 1,879개가 나오는데, 같은 문장이 배치마다 fp16 오차로 미세하게 갈린 것이라
실질은 1,221이다.)

그래서 라벨과 내용이 어긋난다(`out/table79_weight_cluster_audit.csv`).
**top-1 주진단 순도 가중평균 37.3%** — 이름표가 실제로 맞는 환자가 3명 중 1명꼴이다.

| 군집 | 붙은 이름 | n | 실제 top-1 주진단 | 비중 | 고유 주진단 수 | chapter 순도 |
|---|---|---|---|---|---|---|
| 9 | 당뇨성 케토산증 | 1,009 | DKA | **7.9%** | 158 | 33.7% |

| 29 | 고관절 골절 | 374 | Intertrochanteric fx | **9.6%** | 140 | 71.7% |

반대쪽 끝은 반대로 극단이다:

| 군집 | n | 고유 주진단 수 | top-1 비중 |

CCS 는 이 둘을 `Adlt resp fl` 하나로 묶는다 — 1번에서 CCS 가 필요하다고 한 이유가 이거다.

## 5. 실루엣은 "의학적으로 옳은가" 를 재지 않는다

같은 라벨을 두 좌표계에서 재 봤다(`out/57_ccs_track.json`):

| 분할 | 기본 임베딩에서 | 가중치 임베딩에서 |
|---|---|---|
| CCS 주진단 범주 | **−0.060** | **+0.208** |
| ICD-9 챕터 | −0.049 | +0.061 |
| 가중치 k-means k=30 | −0.060 | **+0.383** |
| 기본 k-means k=25 | **+0.049** | −0.085 |

**의학 표준인 CCS 가 좌표계만 바꾸면 −0.060 에서 +0.208 로 뛴다.** 라벨은 한 글자도
안 바뀌었다. 그리고 어느 공간에서든 1등은 **그 공간에서 k-means 를 돌린 라벨**이다.
실루엣은 "이 라벨이 이 좌표계에서 뭉쳐 있나" 를 재는 것이지 임상적 타당성이 아니다.

쐐기 하나 더. 가중치 공간에서 임베딩을 아예 안 쓰고 **SEQ1 최빈 29개 코드 + 기타**로
사전 조회만 한 분할이 실루엣 **0.185** 를 받는다. 챕터(0.061)의 세 배다.
그리고 k 를 올리면 실루엣은 k=50 에서 **0.459** 까지 단조 증가한다 — 엘보가 없다.
k=30 은 "가장 예쁜 k" 가 아니라 규칙 B(모든 시드 최소군집 ≥100)가 뱉은 최대 k 일 뿐이다.

**논문에 실루엣 0.38 을 단독으로 쓰면 안 된다.** 쓰려면 위의 w 스윕 표를 같이 실어야 한다.

## 6. 두 트랙은 독립이 아니다 — "교차검증" 이라고 부를 수 없다

| 쌍 | AMI | ARI |
|---|---|---|
| CCS vs 가중치 k-means | **0.626** | 0.207 |
| 챕터 vs 가중치 k-means | 0.521 | 0.218 |
| CCS vs 챕터 | 0.545 | 0.150 |
| CCS vs 기본 k-means k=25 | **0.133** | 0.018 |

Track 2 의 챕터 순도가 77.1% 다. Track 2 는 Track 1 을 **잘게 쪼갠 것**에 가깝다.
독립된 두 방법이 같은 답에 도달한 게 아니라, 같은 정보(주진단 코드)를 두 번 쓴 것이다.

이건 전달물 §2(큰 군집의 최빈 진단은 군집 특징이 아니다)와 같은 이야기다.
