# 5개 저장소 전처리(preprocessing) 방식 비교

> 대상: `SafeDrug/data/processing.py`, `CausalMed/data/mimic3/processing.py`, `MR-DTR/data/processing_mimic-iii.py`, `DrugRecommendation/data/processing.py`, `HI-DR/data/processing_iii.py` (+ 각 저장소의 `ddi_mask_H.py`)
> `04_데이터자원_비교.md`가 "최종 산출물 파일이 서로 겹치는가"를 다뤘다면, 이 문서는 **그 산출물을 만드는 코드 로직 자체가 저장소마다 어떻게 미세하게 다른가**를 다룬다. 다섯 스크립트 모두 SafeDrug 원본을 복사한 뒤 일부만 고친 형태라, 함수명·컬럼명까지 거의 동일하지만 **필터링 순서, 적용 여부, 그래프 가중치 방식** 등에서 실질적 차이가 있다. 피처 추가 연구를 할 때 "어느 저장소 기준으로 재현하느냐"에 따라 베이스라인 통계 자체가 달라지므로 반드시 확인이 필요하다.

---

## 0. 공통 뼈대

다섯 저장소 모두 다음 순서를 그대로 따른다: **① 약물/진단/시술 원자료 클렌징 → ② NDC→ATC 코드 매핑 → ③ 방문≥2 필터 → ④ 3-테이블 inner join → ⑤ Voc(어휘집) 생성 → ⑥ 환자별 시퀀스(records_final.pkl) 생성 → ⑦ EHR 공출현 그래프 + DDI 인접행렬 → ⑧(별도 스크립트) BRICS 화학 마스크.**
아래 표들은 이 8단계 각각에서 저장소별로 무엇이 다른지를 정리한 것이다.

## 2. NDC → ATC 코드 매핑 — `codeMapping2atc4()` / `ndc2atc4()`

| 항목 | SafeDrug (`processing.py:90`) | CausalMed (`processing.py:34`) | MR-DTR (`processing_mimic-iii.py:35`) | SubRec (`processing.py`) | HI-DR (`processing_iii.py:35`) |
|---|---|---|---|---|---|
| 결과 컬럼명 | `ATC3` (원래 함수명 그대로) | `NDC`로 rename(혼동 유발) | `NDC`로 rename | `NDC`로 rename | `NDC`로 rename |

| 자르는 자리수 | `x[:4]` (4글자 = ATC3 레벨) | `x[:4]` | `x[:4]` | `x[:4]` | `x[:4]` |

→ **결과적으로 다섯 저장소 모두 최종 약물 코드 granularity는 동일(ATC 4글자 접두)**이지만, SubRec만 매핑 원본 CSV의 컬럼명이 `ATC5`라는 점이 특이하다(즉 SubRec이 참조하는 `ndc2atc_level4.csv`의 실제 헤더가 다른 저장소 사본과 다를 가능성 — `04_데이터자원_비교.md`에서 "완전 공통 파일"로 분류했던 것과 배치되는 지점이니, 코드가 실제로 이 컬럼명에 의존한다는 사실은 새로 확인된 것).

## 4. 약물 상위 300개 필터 — `filter_300_most_med()` — **적용 여부 자체가 다름**

| 저장소 | 적용 여부 | 근거 |
|---|---|---|
| SafeDrug | ✅ 적용 (`processing.py:483`) |
| CausalMed | ✅ 적용 (`processing.py:318`) — 단, **SMILES 존재 필터 이후**에 적용 |
| SubRec | ✅ 적용 (`processing.py`) — CausalMed와 동일 순서 |
| HI-DR | ✅ 적용 (`processing_iii.py:342`) |
| **MR-DTR** | **❌ 미적용 — main에서 호출 자체가 주석 처리됨**(`processing_mimic-iii.py:417`: `#med_pd = filter_300_most_med(med_pd)`) |

→ **MR-DTR만 유일하게 "상위 300개 약물" 컷오프를 걸지 않는다.** 대신 SMILES 매핑 파일(`atc3toSMILES2.pkl`)에 존재하는 약물로만 필터링하므로(아래 5절), 실질적인 약물 종류 수는 그 SMILES 사전의 크기에 좌우된다 — 다른 저장소보다 더 많은(혹은 다른) 약물 종류가 최종 어휘집에 남을 가능성이 있다.

### 4-1. SMILES 매핑 확보 방식 — **자체 계산 vs 사전 로드**

| 저장소 | 방식 | 코드 근거 |
|---|---|---|
| **SafeDrug** | **자체 계산**: `drugbank_drugs_info.csv`에서 약물명→SMILES 딕셔너리를 만들고, ATC3별로 최대 3개 SMILES를 골라 `atc3toSMILES.pkl`을 새로 생성(`ATC3toDrug()` + `atc3toSMILES()`, `processing.py:59-86`) | 유일하게 원자료로부터 SMILES 매핑을 직접 구축 |
| CausalMed | **사전 로드**: `input/idx2drug.pkl`을 읽어(`dill.load`) 그 key에 속하는 약물만 필터(`processing.py:316-317`) | 생성 로직 없음, 이미 만들어진 자산을 재사용 |
| MR-DTR | **사전 로드**: `./atc3toSMILES2.pkl` 로드(`processing_mimic-iii.py:414-415`) | 파일명이 다른 4개와 다름(`2` 접미사) — `04_데이터자원_비교.md`에서 지적한 HI-DR MIMIC-IV 산출물명과의 일치 지점 |
| SubRec | **사전 로드**: `./idx2SMILES.pkl` 로드 | CausalMed와 동일 패턴 |
| HI-DR | **사전 로드**: `idx2drug.pkl` 로드(`processing_iii.py:339-341`) | CausalMed와 파일명까지 동일 |

→ **SafeDrug만 SMILES 매핑을 "생성"하고, 나머지 4개는 전부 "이미 만들어진 pkl을 불러와 필터링"만 한다.** 즉 나머지 네 저장소를 원본 MIMIC부터 완전히 새로 재현하려면, 이 사전 구축 pkl들을 SafeDrug 방식으로 먼저 만들어줘야 한다(MR-DTR은 생성 스크립트가 아예 없어 이 지점이 재현 파이프라인의 구멍이라고 `04_데이터자원_비교.md`에서도 지적됨).

## 7. 환자 시퀀스 레코드 — `create_patient_record()` — **레코드 슬롯 개수가 다름**

| 저장소 | admission 리스트 구조 | 근거 |
|---|---|---|
| SafeDrug / CausalMed / SubRec / HI-DR | `[진단idx, 시술idx, 약물idx]` — **3슬롯** | 네 저장소 모두 동일 |
| **MR-DTR** | `[진단idx, 시술idx, 약물idx, timestamp]` — **4슬롯** | `timestamp = (현재 방문 ADMITTIME - 환자의 첫 방문 ADMITTIME).days`(`processing_mimic-iii.py:271`) — 정수형 "첫 방문 이후 경과일수". `get_season()`(계절 파생 피처) 함수도 정의돼 있으나 **호출은 주석 처리**되어 실제로는 쓰이지 않음(`processing_mimic-iii.py:277`) |

→ MR-DTR이 "타임스탬프를 몇 번째 슬롯에, 어떤 값(첫 방문 대비 경과일수)으로 넣는지"까지 확인됨. 새 피처를 추가한다면 이 4번째(혹은 5번째) 슬롯에 이어붙이는 것이 가장 자연스러운 삽입 지점.

## 8. EHR 공출현 그래프 — `get_ddi_matrix()` 내 `ehr_adj` — **이진 vs 가중치**

| 저장소 | ehr_adj 값 | 코드 근거 |
|---|---|---|
| SafeDrug | **이진**(`= 1`) | `processing.py:395-396` |
| CausalMed | 이 스크립트에서 **생성 자체를 안 함**(`ehr_adj_final.pkl` 저장 코드 없음) | `04_데이터자원_비교.md`와 일치 |
| SubRec | **이진**(`= 1`) | SafeDrug와 동일 |
| **MR-DTR** | **가중치 누적**(`+= 1`, 방문 내 동시처방 빈도를 누적 카운트) | `processing_mimic-iii.py:327-328`: `ehr_adj[med_i, med_j] += 1` (주석 처리된 원래 `= 1` 코드가 바로 위에 남아있어 의도적 변경임이 드러남) |
| HI-DR | **이진**(`= 1`) | `processing_iii.py:280-281` (역시 `+= 1`이 주석으로 남아있어, HI-DR이 MR-DTR 계열 코드를 베이스로 하되 **다시 이진으로 되돌렸음**을 시사) |

→ **MR-DTR만 EHR 그래프를 가중치 그래프로 만든다.** HI-DR 코드에 남은 주석(`# ehr_adj[med_i, med_j] += 1`)은 HI-DR 개발자가 MR-DTR(혹은 그 공통 조상) 코드를 참고했다가 이진 방식으로 되돌렸다는 흔적으로 읽힌다 — `04_데이터자원_비교.md`가 지적한 "HI-DR은 별도의 `weighted_confidence_directed_ehr_graph.pkl`로 가중치+방향성을 부여한다"는 관찰과 함께 보면, HI-DR은 **`ehr_adj_final.pkl` 자체는 이진으로 남겨두고, 가중치·방향성은 완전히 별도 산출물(생성 스크립트 미발견)로 분리**했다고 볼 수 있다.

## 9. DDI 인접행렬 — CID→ATC 매핑 확장 방식 차이

| 저장소 | CID→ATC 매핑 후 처리 | 코드 근거 |
|---|---|---|
| SafeDrug / CausalMed / SubRec / HI-DR | ATC3 → 해당 ATC3 접두를 공유하는 **모든 ATC4 코드 쌍**으로 확장(`atc3_atc4_dic` 이중 루프) | `processing.py:407-415`(SafeDrug 기준) |
| **MR-DTR** | 확장 루프가 **주석 처리**되어 있고, CID→ATC3 매핑값을 **그대로 med_voc의 키로 직접 사용**(`processing_mimic-iii.py:342-343`: `if med_voc.word2idx[atc_i] != med_voc.word2idx[atc_j]`) | ATC3-ATC4 확장 없이 1:1로만 매핑하므로, **DDI로 인정되는 약물 쌍의 수가 다른 저장소보다 적을 가능성**이 있음(확장 단계가 빠졌으므로) |

TOPK=40(빈도 내림차순 정렬 뒤 `iloc[-TOPK:]`로 가장 드문 40개 부작용만 DDI로 인정)은 **다섯 저장소 모두 동일**하게 하드코딩되어 있다.

## 10. BRICS 화학 마스크 — `ddi_mask_H.py` (별도 스크립트, `processing.py`와 분리 실행)

| 저장소 | 존재 여부 | SMILES 소스 경로 | `substructure_smiles.pkl` 별도 저장 |
|---|---|---|---|
| SafeDrug | 함수(`get_ddi_mask`)가 `processing.py` **내부**에 있음(별도 파일 아님) | `atc3toSMILES.pkl`(자체 생성분) | ❌ (fracSet을 반환만 하고 별도 저장 안 함) |
| CausalMed | 별도 파일 `ddi_mask_H.py` | `input/idx2drug.pkl` | ❌ |
| **SubRec** | 별도 파일 `ddi_mask_H.py` | `./idx2SMILES.pkl` | **✅ `substructure_smiles.pkl`로 별도 저장**(`ddi_mask_H.py:36`) |
| HI-DR | 별도 파일 `ddi_mask_H.py`(ECFP 방식 대안 코드가 **주석으로** 남아있으나 미사용, 실제로는 BRICS만 사용) | `idx2drug.pkl` | ❌ |
| **MR-DTR** | **파일 자체가 저장소에 없음**(재현 시 직접 작성해야 함) | — | — |

→ 로직(BRICS 분해 → fragment 집합 → 이진 마스크 행렬) 자체는 **네 저장소(SafeDrug/CausalMed/SubRec/HI-DR)가 완전히 동일**하다. 차이는 오직 "어느 SMILES 사전 파일을 읽는가"와 "fragment 집합 자체를 1급 산출물로 저장하는가(SubRec만 Yes)"뿐이다. HI-DR의 주석 처리된 ECFP(Morgan fingerprint) 코드는 "화학 유사도를 다른 방식(반경 기반 지문)으로도 실험해봤다가 최종적으로 BRICS로 되돌아갔다"는 흔적으로 보인다.

## 11. 종합 비교표

| 단계 | SafeDrug | CausalMed | MR-DTR | SubRec | HI-DR |
