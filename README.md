# 의약품 추천 시스템 재현성 연구

MIMIC-III / MIMIC-IV 위에서 동작하는 의약품 추천(medication recommendation) 모델을
직접 재현하고, 재현된 기준선 위에서 확장과 검증을 시도한 기록입니다.

일곱 개의 트랙으로 나누어 두었습니다. 각 트랙은 원래 별개의 저장소에서 진행된 작업이라,
커밋 히스토리도 트랙마다 별도의 뿌리에서 시작해 이 저장소로 합쳐집니다.

## 데이터 정책

모든 트랙이 PhysioNet 인증 데이터(MIMIC-III / MIMIC-IV)를 입력으로 씁니다.
**이 저장소에는 원본 테이블도, 행 단위 파생 산출물(전처리된 환자 레코드, 방문별 예측,
학습된 가중치)도 포함하지 않습니다.** 소스 코드, 테스트, 사람이 쓴 보고서, 그리고
군집·시드 수준으로 집계된 결과 표와 그림만 둡니다.

각 트랙을 실행하려면 PhysioNet 이용약관에 따라 데이터를 직접 내려받아
트랙별 README가 지정하는 위치에 두어야 합니다. 루트 `.gitignore`가 데이터 확장자를
기본 차단합니다.

### 트랙 사이의 관계

트랙 01에서 재현 대상을 고르고, 트랙 02에서 HI-DR을 재현하며 "빔서치 후보 풀"이
성능 상한을 쥐고 있다는 것을 확인했습니다. 트랙 03은 같은 문제를 SafeDrug 계열에서
MIMIC-IV로 옮겨 장기 기능이라는 환자 상태 축을 추가로 넣어 본 것이고,
트랙 04는 재현된 SafeDrug의 정확도가 **어떤 환자군에서** 떨어지는지를 따로 검정한
감사(audit)입니다.
트랙 05·06은 그 격차의 원인을 각각 방문 표현과 DDI 제약에서 찾아본 후속 실험이고,
트랙 07은 "급성 입원 이유를 따로 보면 처방 변화를 더 잘 맞힐 것"이라는 가설을 구현 전에 검증한 기록입니다.

## 각 트랙의 요지

**트랙 02 — HI-DR 재현과 재설계.** HI-DR 위에 얹었던 1차 접근(사후 필터)의 전제
("모델이 약을 과다 추천하니 걸러내야 한다")가 틀렸음을 데이터로 확인했습니다. HI-DR의 방문당
예측 후보 수 20.07과 정답 약물 수 20.16이 사실상 같아 잘라낼 과잉이 없었고, 그런데도
사후 필터는 방문당 정답 약물 1.38개를 함께 지우고 있었습니다. 또 후보 풀 커버리지만 보면
**환자의 직전 방문 처방을 그대로 반복한 집합**(0.6543)이 빔서치 출력 전체(0.6325)보다
정답을 조금 더 담고 있어, 두 집합을 합치는 쪽이 낫다고 판단했습니다(논문의 평가 지표와는
다른 비교이며, 학습 모델과 복사 기준선의 우열은 트랙 07에서 데이터셋마다 다르게 나왔습니다).
그래서 시스템을 "필터"에서
"후보 풀 확장 + 이력 기반 재점수화"로 바꿨고, 구 시스템과 같은 크기로 맞춘 비교 지점에서
Jaccard 0.4550 → 0.5231을 얻었습니다. 다만 실제 배포 threshold의 운영 Jaccard는
약 0.503이며, 이 구분은 보고서 §4에 명시해 두었습니다.

**트랙 03 — SafeDrug + 장기 기능.** SafeDrug 원본이 ICD-10 방문을 버리는 문제를
ICD-9/10 버전 태깅으로 고쳐 MIMIC-IV 레코드를 다시 만들고, TWOSIDES에서 DDI 인접행렬을
새로 구축했습니다. 그 위에 신장·간 기능 검사 피처를 선택적으로 주입하는 SafeDrug 변형과,
신기능·간기능 저하 하위군 지표를 붙였습니다. 현재까지 기록된 실행은 1 epoch · 4명
규모의 GPU 스모크 테스트이며, 본 학습 결과는 아직 없습니다.

**트랙 04 — 군집별 공정성 감사.** SafeDrug을 MIMIC-III 코호트(6,350명 / 15,032방문)로
직접 학습해 test Jaccard 0.508~0.515(시드 0~3, 원 논문 기준 0.511)로 재현한 뒤,
Bio_ClinicalBERT로 임베딩한 진단 텍스트로 방문을 군집화하고 군집별 정확도를 쟀습니다.
진단 수·약물 수·방문 순서를 보정한 뒤에도 군집 간 Jaccard 격차가 풀링 기준 0.061
(p 0.003)로 남았고, 시드 쌍 순위상관 0.90~0.98로 안정적이었습니다. 격차의 정체는
precision 쪽(0.132)이 recall 쪽(0.069)의 두 배였고, 실제 처방 약물의 학습셋 빈도와
상관 +0.71 — 즉 드문 약을 쓰는 환자군에서 더 못 맞힙니다.

**트랙 05 — 급성 attention.** SafeDrug의 코드 합산 풀링을 입원 시점 텍스트 query의 attention으로 바꿨습니다.
Jaccard는 0.508 → 0.518까지 올랐지만 군집 격차는 줄지 않았고, attention은 학습이 끝나면 균등으로 돌아갔습니다.
주진단으로 attention을 지도하면 급성 이유를 실제로 가리키지만(hit@1 56%) 정확도가 떨어집니다.
처방 목적함수는 "급성 이유에 집중"을 보상하지 않습니다.

**트랙 06 — DDI 제약과 불공정.** SafeDrug의 DDI 행렬은 TWOSIDES에서 가장 드문 부작용 40종 중 하나에 성분 쌍 한 개만 걸려도
클래스 쌍 전체를 표시하는 구조라, 스타틴–질산염, 베타차단제–ACE억제제 같은 가이드라인 병용까지 "상호작용"으로 표시합니다.
페널티를 끄면(4시드) 초과 DDI 격차가 절반으로 줄어 유의성이 사라지고, 페널티 부담은 CAD·MI, 심부전+CKD 군집에 몰려 있었습니다.
질환별 허용 목록(W)은 격차를 없애지만, 약물 단위로 추천하는 구조에서는 쌍 단위 안전 예외를 선택적으로 표현할 수 없음을 확인했습니다.

**트랙 07 — 급성/만성 사전검증.** "모델이 직전 처방 복사를 못 넘는다"는 전제는 MIMIC-IV에서만 성립했습니다
(MIMIC-III에서는 모델이 +0.045 앞섬). 급성 라벨은 모델 오류와 맞지 않았고 핵심 약점은 롱테일 약물 recall이었습니다.
MIMIC-IV에서는 kNN 검색 + 직전 처방 기준선(0.494)이 SafeDrug·GAMENet·MICRON(0.440~0.449)을 크게 앞섰지만,
어느 방법도 추가 약물·중단 판단·드문 약은 고치지 못했습니다.
