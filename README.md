# 의약품 추천 시스템 재현성 연구

MIMIC-III / MIMIC-IV 위에서 동작하는 의약품 추천(medication recommendation) 모델을
직접 재현하고, 재현된 기준선 위에서 확장과 검증을 시도한 기록입니다.

네 개의 트랙으로 나누어 두었습니다. 각 트랙은 원래 별개의 저장소에서 진행된 작업이라,
커밋 히스토리도 트랙마다 별도의 뿌리에서 시작해 이 저장소로 합쳐집니다.

## 데이터 정책

네 트랙 모두 PhysioNet 인증 데이터(MIMIC-III / MIMIC-IV)를 입력으로 씁니다.
**이 저장소에는 원본 테이블도, 행 단위 파생 산출물(전처리된 환자 레코드, 방문별 예측,
학습된 가중치)도 포함하지 않습니다.** 소스 코드, 테스트, 사람이 쓴 보고서, 그리고
군집·시드 수준으로 집계된 결과 표와 그림만 둡니다.

각 트랙을 실행하려면 PhysioNet 이용약관에 따라 데이터를 직접 내려받아
트랙별 README가 지정하는 위치에 두어야 합니다. 루트 `.gitignore`가 데이터 확장자를
기본 차단합니다.

### 트랙 사이의 관계

트랙 01에서 재현 대상을 고르고, 트랙 02에서 HI-DR을 재현하며 "빔서치 후보 풀"이
성능 상한을 쥐고 있다는 것을 확인했습니다. 트랙 03은 같은 문제를 SafeDrug 계열에서
MIMIC-IV로 옮겨 장기 기능이라는 환자 상태 축을 추가로 넣어 본 것이고,
트랙 04는 재현된 SafeDrug의 정확도가 **어떤 환자군에서** 떨어지는지를 따로 검정한
감사(audit)입니다.

## 각 트랙의 요지

**트랙 02 — HI-DR 재현과 재설계.** 기존 전제("모델이 약을 과다 추천하니 걸러내야 한다")를
데이터로 반증했습니다. 방문당 예측 후보 수 20.07과 정답 약물 수 20.16이 사실상 같아
잘라낼 과잉이 없었고, 그런데도 기존 사후 필터는 방문당 정답 약물 1.38개를 함께 지우고
있었습니다. 더 나아가 **환자의 직전 방문 처방을 그대로 반복하기만 해도** 정답 커버리지가
0.6543으로 빔서치 출력 전체(0.6325)보다 높았습니다. 그래서 시스템을 "필터"에서
"후보 풀 확장 + 이력 기반 재점수화"로 바꿨고, 구 시스템과 같은 크기로 맞춘 비교 지점에서
Jaccard 0.4550 → 0.5231을 얻었습니다. 다만 실제 배포 threshold의 운영 Jaccard는
약 0.503이며, 이 구분은 보고서 §4에 명시해 두었습니다.

**트랙 03 — SafeDrug + 장기 기능.** SafeDrug 원본이 ICD-10 방문을 버리는 문제를
ICD-9/10 버전 태깅으로 고쳐 MIMIC-IV 레코드를 다시 만들고, TWOSIDES에서 DDI 인접행렬을
새로 구축했습니다. 그 위에 신장·간 기능 검사 피처를 선택적으로 주입하는 SafeDrug 변형과,
신기능·간기능 저하 하위군 지표를 붙였습니다. 현재까지 기록된 실행은 1 epoch · 4명
규모의 GPU 스모크 테스트이며, 본 학습 결과는 아직 없습니다.

**트랙 04 — 군집별 공정성 감사.** SafeDrug을 MIMIC-III 코호트(6,350명 / 15,032방문)로
직접 학습해 test Jaccard 0.508~0.515(시드 0~3, 원 논문 기준 0.511)로 재현한 뒤,
Bio_ClinicalBERT로 임베딩한 진단 텍스트로 방문을 군집화하고 군집별 정확도를 쟀습니다.
진단 수·약물 수·방문 순서를 보정한 뒤에도 군집 간 Jaccard 격차가 풀링 기준 0.061
(p 0.003)로 남았고, 시드 쌍 순위상관 0.90~0.98로 안정적이었습니다. 격차의 정체는
precision 쪽(0.132)이 recall 쪽(0.069)의 두 배였고, 실제 처방 약물의 학습셋 빈도와
상관 +0.71 — 즉 드문 약을 쓰는 환자군에서 더 못 맞힙니다.
